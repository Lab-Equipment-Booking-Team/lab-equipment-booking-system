Security & Design Principles

  • Werkzeug Password Hashing: Passwords are never stored in plain text.
  • Server-Side RBAC: Role enforcement via custom decorators protecting all staff and student endpoints.
  • Integrity Constraints: Deletion of equipment with historical bookings is strictly prevented.
  • Discrete Overlap Calculations: Only true time-range conflicts for approved bookings block slots.
  • In-Memory Test Database: Automated tests run without modifying persistent local data.
  • Automated CI: GitHub Actions verifies Ruff linting and Pytest coverage on every push.
